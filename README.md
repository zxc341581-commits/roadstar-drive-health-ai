# Drive Health AI

차량 주행 기록에서 브레이크·타이어에 부담을 줄 수 있는 이벤트를 찾아 운전습관 개선과 정비 예산 관리를 돕는 앱입니다.

## 릴리스 APK와 실행 방법

- 버전 **0.5.5** (versionCode 13), 패키지 `com.drivehealthai.demo`, Android 9(API 28) 이상.
- APK 위치는 [`apk/로드스타_DriveHealthAI_release.apk`](apk/로드스타_DriveHealthAI_release.apk)입니다. 로드스타 팀의 공모전 제출용 파일입니다.
- 설치 후 **Drive Health AI**를 실행합니다. 개발 환경에서는 `adb install apk/로드스타_DriveHealthAI_release.apk`로 설치를 시도할 수 있습니다. 이 릴리스는 v0.2.1과 같은 인증서를 사용합니다. v0.2.0과는 인증서가 달라 v0.2.0 위에 덮어 설치할 수 없습니다. 제거하면 기기에 저장된 기존 주행 기록과 견적이 삭제됩니다.
- [`app/src/main/assets/index.html`](app/src/main/assets/index.html)을 Chromium에서 열어 같은 웹 화면과 분석 엔진을 실행할 수 있습니다. 설치형 시제품에 API 키나 계정은 필요하지 않습니다.

## 시연 순서

1. **차량 데이터 → 가상 차속 재생**에서 급감속 3건과 횡가속도 미수집 표시를 확인합니다.
2. **소모품 관리**에서 브레이크·타이어 코칭을 확인합니다. HEV·EV를 선택하면 회생제동 관련 안내가 표시됩니다.
3. **주행 분석 → CSV 분석**에서 [기준 예제](demo/baseline.csv)를 불러옵니다. **운전 코칭**에서 현재 기록을 기준으로 고정한 뒤, [개선 예제](demo/improved.csv)를 불러옵니다. 두 예제는 각각 10 km 미만이어서 횟수로 비교합니다. 두 기록 모두 누락 없이 10 km 이상이고 비교 조건을 확인한 경우 거리당 변화율을 표시합니다. 두 파일은 시연용 가상 기록입니다.
4. **My Car Budget**에서 주행습관과 연결된 부품 점검 안내를 확인한 뒤, 참고가를 가져오거나 견적을 직접 입력합니다. 예정 월을 다음 달로 정해 저장하면 월 예산에 반영됩니다.
5. 차량 신호를 제공하는 Android Automotive 환경에서는 정차한 P단에서 **차량 기록 시작**을 누르고 권한을 허용한 뒤 주행합니다. 주행 후 정차 상태로 P단에 복귀하면 리포트를 여는 흐름을 구현했습니다.

차량 기록은 AAOS `CarPropertyManager`의 `PERF_VEHICLE_SPEED`(m/s)와 `GEAR_SELECTION`을 사용합니다. v0.2.2는 Android 10 이상에서 차량 서비스가 연결 준비를 알린 뒤 신호 읽기를 시작합니다. 연결 대기 시간은 5초이며 서비스가 끊기면 기록을 종료하고 저장된 자료를 보존합니다. 차량에서 차속·선택 기어 읽기 권한과 속성 지원이 필요합니다. 일반 Android, Pleos 에뮬레이터·실차에서 이번 차량 연동의 실행 검증은 수행하지 않았습니다. 가상 차속과 CSV 분석은 이 권한 없이 사용할 수 있습니다. 시연 영상은 브라우저에서 녹화했으며 차량 신호는 가상 입력입니다. [Pleos 차량 차속 문서](https://document.pleos.ai/en/docs/pleos-only/vehicle-app-developer-guide/vehicle-app-faq)

## 차량용 화면

- 가로 화면은 왼쪽 메뉴를 고정합니다. 좁은 앱 창에서는 메뉴가 위로 이동하고, 상세 카드는 한 열로 표시됩니다.
- 주요 버튼과 입력칸은 가로 기준 최소 56 CSS px 높이, 좁은 창에서는 최소 48 CSS px 높이입니다. 시작 시 시스템 테마를 따르며 상단 버튼에서 주간·야간을 선택할 수 있습니다.
- 차량 기록 중에는 기존 기록 전용 화면을 유지합니다. Android에서 시스템 바, 화면 컷아웃 및 키보드의 인셋을 WebView에 반영합니다.
- 화면 설계 참고 자료 [Pleos Connect UI Design Guide](https://document.pleos.ai/docs/connect/guide/docs-design/Introduction/intro) · [Display Layout](https://document.pleos.ai/en/docs/connect/guide/docs-design/getting-started/layout)

## 계산과 보관

CSV 헤더는 `t_s,speed_kmh,long_ms2,lat_ms2`입니다. 시간은 초, 차속은 km/h, 가속도는 m/s²입니다. 거리당 빈도는 유효 주행 10 km 이상이며 누락 구간이 없는 기록에서 표시합니다. 10 km는 시제품의 표시 기준입니다. 이벤트의 100km당 빈도는 **이벤트 수 ÷ 분석 거리(km) × 100**으로 계산합니다. 급감속 기준은 차속 5 km/h 이상인 관측 구간에서 감속 크기 3.0 m/s² 이상이 0.5초 이상 지속되는 시제품 규칙입니다. 가속 기준은 3.0 m/s², 횡가속 기준은 절댓값 3.2 m/s²입니다. 누락 구간은 거리·이벤트에 포함하지 않습니다. 차량 차속만으로 분석할 때는 급코너링을 미수집으로 표시합니다.

CSV와 차량 기록은 각각 최근 분석과 비교 기준을 기기에 저장합니다. 다음 달 예산은 해당 월의 등록 견적·교체 전망과 입력한 월 보험료를 합산합니다. 예정 월이 없는 기존 견적은 목록에 그대로 남습니다. 미국 참고가는 사용자가 선택해 저장할 때 예산에 들어갑니다. 브레이크는 패드 교체비 [RepairPal](https://repairpal.com/estimator/brake-pad-replacement-cost), 타이어는 16–20인치 사계절 타이어 4개 제품가 [Discount Tire](https://www.discounttire.com/blog/tire-prices-guide)를 사용합니다. 주행 리포트는 규칙으로 주행 이벤트를 분석합니다. 브레이크 패드와 타이어의 잔여거리·비용 시나리오는 두 번의 실측값으로 별도 계산합니다. `docs/`에는 후보 소스를 개발하던 당시의 연구 및 검증 기록이 들어 있습니다. 당시 문서에 적힌 APK 빌드 대기 상태는 이번 릴리스에서 해소했습니다.

## 부품과 비용 전망

- **개별 부품 수명 예측**은 동일한 브레이크 패드 또는 타이어의 두 번의 실측 두께를 사용합니다. 마모율(mm/km)은 두께 감소량을 두 점검 사이의 주행거리로 나눈 값입니다. 잔여거리는 최근 두께에서 지정한 점검 기준 두께를 뺀 값을 마모율로 나눠 계산합니다. 급감속·급코너링은 함께 표시하는 주행 단서입니다.
- **정비비 절약 시나리오**는 같은 연간 거리에서 운전자가 입력한 마모율 감소 가정을 비교합니다. 연간 마모량을 새 부품 기준 두께와 점검 한계 두께의 차이로 나눈 뒤 교체비 범위를 곱해 연간 정비비 적립 추정치를 구합니다. 개선 전후 차이는 실제 절약액과 별개의 계획 수치입니다.
- **통합 미래 지출**은 다음 달부터 선택한 1·3·6·12개월 동안 예정된 정비 견적과 직접 입력한 월 보험료를 월별로 합산합니다. 월을 지정하지 않은 견적과 예상에만 표시한 부품 교체비는 자동 합산하지 않습니다. 보험료가 입력되지 않으면 정비비만 표시합니다.

## 메뉴와 차량 데이터

- **주행 분석**은 속도 그래프와 급가속·급감속을 표시하고, 최근 실제 수집 및 CSV 기록 최대 12건을 10 km 기준으로 분류합니다. CSV 표준 헤더 뒤에 선택 열 `engine_rpm`을 붙일 수 있습니다. 연속 RPM 표본이 있는 구간의 시간 가중 평균과 정차 상태 엔진 회전 시간을 계산합니다. 차량 연결 모드는 AAOS 차속·기어를 사용하며 RPM은 제공하지 않습니다.
- **소모품 통합 관리**는 엔진오일, 타이어, 브레이크 패드, 12V 배터리, 변속기 오일, 냉각수, 엔진 에어필터와 캐빈 필터를 다룹니다. 전기차에서는 엔진오일과 엔진 에어필터를 숨깁니다. 사용자가 매뉴얼에 맞춰 고른 일반·가혹 운행 조건별 기준을 분리해 저장하고 적용합니다. 점검은 최근 점검 또는 교체 이력, 교체는 최근 교체 이력을 기준으로 각각 다음 일정을 계산합니다. 소모품 카드에는 등록 기준 도달, 다음 달까지 예정, 기준 등록됨, 정보 필요 상태를 점검 우선순위대로 표시합니다. 예상 월 주행거리 입력 시 거리 기준 도달 월을 추정합니다. 정비소 점검에서 입력한 교체 기준을 사용하세요.
- **운전 코칭**은 비교 가능한 두 주행의 거리당 이벤트 차이를 유지하고, 주행 유형과 부품별 권장 행동을 보여줍니다. 분석과 코칭은 기기에서 실행하는 규칙 기반 기능입니다. 학습형 소모품 예측 모델은 향후 실제 주행·정비·교체 시점과 실측 데이터로 고도화할 계획입니다.
- **차량 데이터**는 차량 모델, 연식, 파워트레인, 누적 주행거리와 교체·점검·정비 기록을 이 기기에 저장합니다. 교체와 점검은 주기 계산의 시작점을 각각 다르게 적용합니다.
- **My Car Budget**은 선택한 기간(기본 3개월)의 직접 등록 견적과 소모품 교체 전망, 월 보험료를 합산합니다. 예상 월 주행거리로 거리 기준 도달 월을 추정하고, 달력 기준과 비교해 먼저 도달하는 일정에 반영합니다. 등록 견적이 있으면 같은 부품의 자동 교체 전망을 견적으로 대체합니다. 비용 미등록 점검·교체는 일정표에만 표시하며 이번 달 일정과 이미 도달한 기준은 별도 안내합니다. 점검·교체별 거리 초과량은 `현재 주행거리 − 해당 주행거리 기준`으로 표시하고, 날짜 기준이 지났으면 경과 일수를 표시합니다.

## 미국시장 확장

- 차량 프로필에서 Tucson, Santa Fe, Elantra, Kona 및 IONIQ 계열의 지원 모델을 선택하면 동력원이 입력됩니다. 전기차에서는 엔진오일, 엔진 에어필터, 내연기관 변속기 오일을 제외합니다. 이 모델 목록은 정비 주기를 자동으로 지정하지 않습니다. 연식과 동력원에 맞는 [Hyundai USA 정비 기준](https://www.hyundaiusa.com/us/en/maintenance-schedule)을 확인해 입력하세요.
- 한·영 UI 전환, km/mi 입력·표시, 미국 모델·연식별 매뉴얼 데이터 연동과 ZIP 코드별 정비 견적은 향후 확장 항목입니다. 가상 시연의 주기와 비용은 예시입니다.

## 다시 빌드하기

Android SDK Platform 35, Build Tools 35.0.0, Java 컴파일러, zip과 unzip을 준비합니다. 로컬 서명키를 마련하고 `ANDROID_SDK_ROOT`, `DRIVE_KEYSTORE`, `DRIVE_KEY_ALIAS`, `DRIVE_STORE_PASS`, `DRIVE_KEY_PASS`를 설정한 뒤 `bash scripts/build-release.sh 'apk/로드스타_DriveHealthAI_release.apk'`를 실행합니다. 필요한 경우 `BUILD_TOOLS_DIR`, `ANDROID_JAR`, `ANDROID_CAR_JAR`, `ECJ_JAR`로 설치 경로를 지정합니다. 서명키와 비밀번호는 저장소에서 제외합니다.
